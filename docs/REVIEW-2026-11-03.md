## Second review and scope limits

The second investigation covered eleven selected files at
`2c5a625ce245be2a5ec2f0b30633d708b50afb9e` and returned nine further findings.
Its processing completed, but its gate remains `ERROR`: reviewers disclosed
omitted neighbouring context. Separate reviewers reading each file does not
establish that every caller/callee interaction was investigated. The strict
scope policy was retained. Missing or malformed `refusal.skipped` metadata is
also rejected, with explicit negative controls.

| Finding | Disposition and control |
| --- | --- |
| Clean filters can run through Git status/working diff; shared prefix is insufficient | Reproduced with a marker-writing clean filter. Metadata now compares tree/index IDs and raw `hash-object --no-filters` results; the native CLI shares the tree parser. No status or working-diff invocation is used. |
| Ordinary preseeded state can be tracked or contain loader inputs | Tracked review state and unmanaged workspace-root entries are refused before the reviewer runs. Known configuration/ignore files are written privately; current-run and exact-byte requirements still apply to checkpoint records. |
| Historical reports consume the active-state traversal budget | Historical report contents are not revisited as reviewer inputs. Fresh output paths remain validated; active checkpoint data retains an explicit bound and documented external archival procedure. |
| Full scans refuse symlinks, submodules or oversized files | Deliberate supported-input boundary. No files are silently omitted from a claimed complete scope. Use an explicit narrower file manifest and record exclusions. |
| Manual/audit expectation status can remain passed against stale current context | Reproduced independently of the aggregate gate. Assessments now apply current subject/ancestry/input/configuration checks; changed-context and unchanged/known-ancestor controls cover both outcomes. |
| Elapsed duration differs from wall-clock timestamp span | These are independent clock domains: `Instant` enforces deadlines, while wall timestamps identify observations. Equality would reject valid runs after clock adjustment and would not authenticate imported receipts. The distinction and deadline control are explicit. |
| Legitimate symlinked output ancestors are rejected | Deliberate output-path contract. Canonicalise an explicitly trusted root before invocation; the runner does not silently follow arbitrary output links. |
| Reaping the process leader before delayed group signalling allows PID reuse | The runner now observes Linux exits with safe `waitid(WNOWAIT)` while retaining the leader through final signalling, then reaps. A lost-child-ownership control verifies that no further group signal is sent. Unsupported execution platforms are refused before spawning. |

Local/CI checks and a real protocol smoke review are separate from these broad
production investigations. A smoke test can qualify the adapter's completion
path; it cannot turn either retained production `ERROR` receipt into `PASS` or
establish complete security coverage. Host baseline issues remain in the host's
review record, with actual comparison evidence rather than an inferred label.
